01 / reference lock

Preserve the visible flight.

A visual, media-heavy marketing site is a different workload from a documentation corpus. Full-bleed video, changing header states, forms, galleries and WebGL trackers all belong to the reconstruction.

  • Homepage / settled geometrySeven heading boxes, footer and total body height match both models at 1440×1000, 768×1000, 390×844 and 320×844.
  • Tracker / native browser runtimeVehicle and follow-Dragon heading, canvas, telemetry and footer geometry match all four fixtures. Representative pointer drag and keyboard activation work.
  • Navigation / scrolling contractMobile down-scroll hides the header; up-scroll restores it. Delivered dropdown positioning and nav-owned menu scrolling are retained.
  • Corpus / publication audit829 pages and redirects plus 89 HLS manifests. All 805 reference routes represented; zero unclassified missing local references.
  • Forms / local behaviorSource-derived required fields, distinct email grammars, conditional fields and the lead form’s 449/450/500 counter boundaries.
  • Page families / representative states712 missions, 143 galleries / 411 slides, 21 crew missions, 22 multi-webcast lists and 3,059 career records are inventoried.
Parity maturity was accepted for closeout. Exact compared geometry is not exhaustive animated-pixel, physical-touch, all-filter or private-backend certification. Private submissions/CAPTCHA/newsletter success are unavailable and never fabricated. Two inherited malformed references remain classified. Browser codec and external-playback qualifications remain below.
02 / maintained source

Two ways to own the reconstruction.

Nift spacex / authored source

Keep repeatable content authoritative.

Structured JSON, prose and native HTML partials maintain mission, homepage and careers content. Shared Nift templates compose them. This is not a Markdown conversion benchmark.

Maintained structured content + partials
→ Nift dependency evaluation / composition
→ HTML and HLS publication
Nift spacex-agent / rendered source

Maintain the recovered HTML directly.

Agents edit maintained rendered markup with shared native partials. No recovery script or renderer runs during routine publication.

Maintained rendered HTML + partials
→ Nift dependency evaluation / composition
→ HTML and HLS publication

Both retain ordinary browser JavaScript for animation, validation, native/HLS video and WebGL telemetry. Internal links, images, videos, fonts and runtime assets use @path; Nift handles publication paths, not browser physics.

03 / build telemetry

The public reference is not a timing participant.

No private SpaceX build measurements exist in this experiment. The two columns below compare the reconstructed Nift projects only.

Five serialized samples per scenario on an Intel i7-12700H, 20 logical CPUs, Nift 4.10.0 with the maintained automatic thread setting. Medians; zero-based linear scales. Maximum individual process RSS is measured by GNU time, not aggregate memory. No sampled tree-RSS cohort was captured.

Warm full uses nift build --all. Fresh application state clears generated Nift dependency metadata before nift build; it does not flush OS caches. Unchanged uses the same normal production command. Full and fresh build all 918 outputs.

These are complete routine publication times for this architecture: dependency checks, maintained-source evaluation, path resolution, templates and writes. There is no routine converter, frontend bundler, backend compiler, search stage, asset acquisition or postprocessor. Pinned media acquisition is setup-only; maintained static files are already under public. Nift’s internal operations are one measured phase, not separately timed internals.
04 / changed-input telemetry

Measure the next edit, including memory.

One mission rebuilds one output; three missions rebuild three; homepage changes rebuild three including aliases. Shared layout, navigation, CSS and JS/cache-key changes rebuild 783 pages. Runtime JSON is already a maintained publication asset and requires no HTML rebuild. A route add or rename builds one output; deletion removes the old output.

These are controlled maintained-source probes. Shared markup/JS probes add harmless comments, CSS adds an unused rule, and metadata adds valid JSON whitespace. Route tracking and source mutation occur before the timed publication command. Every incremental workload reports RSS from those same five samples.

Ten lifecycle correctness checks per project match incremental and forced bytes, including source restoration and absence of renamed/deleted outputs. Fresh GitHub checkouts after pinned setup reproduce all 918 generated files exactly and serve homepage/JS through the normal preview script.

Keep the remaining cost visible.

The rendered model is faster in full publication; it does not uniformly reduce peak RSS. Shared-shell fan-out remains the major iteration cost. Output contains approximately 102 MB HTML, including roughly 81 MB repeated inline CSS, plus 2.18 MB external JavaScript. Inline CSS is already included in HTML bytes, not an additional asset total. Externalizing appropriate shared styles is future work requiring its own parity pass.

No Nift core changes, benchmark-specific cache, thread tuning or speculative optimization layer were introduced. The approximately one-second publication profile did not justify destabilizing the accepted rendering architecture.

05 / preservation boundary

Playback reference, not a video archive.

Offline-preserved

What the observed site needs.

HTML, delivered bundles, images, fonts, hero/background video, posters, thumbnails, tracker textures and captured initial HLS playback windows. Seven pinned maintained-asset releases represent 3,072 paths / approximately 3.858 GB of accepted bytes.

Remote-referenced

What the download catalogue needs.

The manifest records 61 remote-referenced media entries (about 346.6 GB in declared content lengths). The 320.6+ GiB download-only catalogue remains at original public URLs with route association, role, content type, content length, status and available response metadata. Large payloads were not mirrored just to demonstrate working download links.

Uncaptured HLS tails retain canonical URLs; complete offline streams are not claimed. Original HEVC bytes remain intact, including a clip unsupported by this test browser. External YouTube URLs remain intact; offline parity preview blocks third-party playback. Background videos were not replaced with posters to manufacture parity.

The maintained projects each acquire their required publication assets once. Heavy canonical reference, release transport and benchmark logs stay outside Labs. Normal build/serve does not read sibling reference directories.

06 / engineering judgment

Prefer the authored source of truth.

Humans + agents both edit

Preferred: Nift spacex — authored source.

Structured authoritative records and shared native templates are easier to review and maintain than coordinating repeated rendered markup.

Agents implement / humans direct

Preferred: Nift spacex — authored source.

Ordinary iteration is already sub-second. The rendered model’s full-build advantage does not outweigh the clearer content model for this corpus.

If reconstruction effort is already paid, the same preference holds. Nift spacex-agent remains a viable direct-HTML maintenance model and the faster full-publication path. This judgment compares these two reconstructed repositories, never SpaceX’s unseen private source.

Is this kind of site a good Nift fit?

Yes, within the demonstrated public surface: Nift composes a substantial static route corpus cheaply while native browser runtimes retain the media, animation and tracker behavior.

The work also shows the real reconstruction cost, extensive parity work, CSS duplication and unavailable private-service boundaries. It supports Nift’s architectural suitability for this class of public site, not a claim that SpaceX should migrate its private implementation.

Migration-init dogfooding

nift init --migration guidance should explicitly support frozen observable-output reconstruction when source is unavailable, remote-only download media, authored/rendered recovery choices, scoped browser parity and absent incumbent build benchmarks. Those are recorded guidance lessons; no core change was made during this experiment.
