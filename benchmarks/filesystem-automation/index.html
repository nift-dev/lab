Read the operation, not just the number

Small reads include an in-language checksum over every byte. Large reads load every byte but aggregate only endpoints; full SHA-256 fixture checks happen outside timing. Stream writes include source reads. Copy checks paths and bytes, not permissions. Delete removes files and leaves directories.

Mirror compares a portable, noncryptographic fingerprint and preserves identical files. It is not a security digest. Timestamp detection and native SHA-256 are unavailable in this Nift snapshot. Mtime-only detection misses changed bytes with restored timestamps; content detection ignores time-only changes.

Generation prefixes each input and writes a sorted manifest. The mixed workflow ignores group19, generates selected .md files, copies .dat assets and writes a manifest. Traversal still visits ignored paths. It is a controlled project workflow, not a website build.

Machine / correctness / scope

AMD EPYC 7642 / Ubuntu 24.04.4 / kernel 6.8.0-134 / ext4 / 4 vCPU, 8 GiB. Four-CPU affinity. Fresh invocation includes launch and exit; booted timing starts after readiness and ends at the complete response. Every sample uses a new runtime. CPU and wait4 RSS cover launch/lifetime even for booted rows. RSS includes a pre-exec supervisor-image floor; it cannot rank runtime memory efficiency.

77 scenarios / 752 supported cells / 14,264 measured observations + 752 warmups. One separate warmup per supported cell; rotated runtime order; no outlier deletion. Fixtures are restored, fully read and statted outside timing. Exact result sets and SHA-256 output trees are independently checked. Low-count stress tails are descriptive.

Filters stat every file before selection; extension/group/size are correlated. Basename selectivity and extension/prefix/size filters are separate cohorts. No symlink, permission, glob, physical-bandwidth or portability claim. Canonical evidence retains all distributions and reset receipts.

Would I actually choose Nift?

Qualitative practitioner assessment / not benchmark evidence

Nift is usable for bounded Nift-owned automation, but large-tree throughput is weak here. At 10k files, its walk is 1.350s, stat 3.055s and mixed workflow 8.553s; Go takes 39.767ms, 73.877ms and 300.728ms. I choose .f for small project-local tasks when its APIs suffice; Python or Go for a new general release utility.

Cloud walk/stat traces show 21,373/41,373 metadata queries at 10k files. Stat allocation profiling records 5,578,191 calls. A minimal read-loop chained call executes three times; explicit binding executes once. Accepted adapters use binding and pass exact checks. Core remains untouched.
