Execution models

The primitive travels with the number.

Nift

Native threads, snapshot captures, async pool, shared atomic/mutex handles.

Python

asyncio waits, spawn processes for CPU, threads for files/processes; ordinary GIL build.

Node / Bun

Promises and timers for waits; worker_threads for CPU and SAB atomics.

Go

Compiled goroutines, channels, sync and atomic primitives.

When one fails

Nift recoverable errors reach await; repeated await re-observes the error and successful siblings finish. No public thread/future cancellation API was found in this frozen source: cooperative atomic stop tokens are explicit. Python task cancellation, JS AbortSignal and Go context cancellation passed separate probes. These are different contracts, not equal fail-fast semantics.

12 / memory

Keep work alive.

All tasks are staged behind a gate while tree RSS is sampled. Final Nift10k held tasks are outside the certified matrix: a separate probe timed out before READY at45seconds with sampled peak4,137.840MiB below its6GiBguard. This time-censored diagnostic is not a plotted wall/memory result or proof of8GiBinfeasibility. Queued Nift futures need not have started running. Shared pages may be double-counted; this is not unique physical memory.

AI-DX / qualitative judgment

Which tool would I choose?

Human + agent: Go for standalone high fan-out/CPU concurrency; Nift for bounded orchestration already in a Nift project. Agent-primary: the same conditional choices. Explicit captures, typed handles and join/await help an agent inspect ownership, but they do not erase the measured throughput gaps or retained-runtime slowdown.

Exact output/error and worker-limit contracts were audited. Autonomous authoring success, race repair and recovery productivity were not measured. Harness JSON is not product-native structured feedback. Prefer concise helpers preserving explicit contracts over duplicated metadata; that is design judgment, not a timing result.

Large scheduling and queue-throughput deficits remain visible in the current peer comparisons. Node/Bun remain natural choices for an existing JS async application; networking capacity was not tested.
