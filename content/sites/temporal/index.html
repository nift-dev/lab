Event 001 / architectures

Three implementations. Two Nift source models.

Upstream Temporal Docusaurus is the original implementation. Nift temporal (authored-source) and Nift temporal-agent (rendered-source) are independent migrations with different maintained inputs.

Nift temporal (authored-source)

Maintained Markdown/MDX/frontmatter
+ structured references
→ pinned corpus compiler / retained component renderer
→ transient HTML + derived navigation/downloads/LLM products
→ Nift composition
→ publication + retained React islands

Nift temporal-agent (rendered-source)

Maintained HTML + explicit metadata/navigation
+ pre-derived downloads/LLM views
→ retained shell/island composition
→ Nift composition
→ publication + retained React islands

React remains where appropriate. The authored path uses the pinned MDX compiler and retained components; the rendered path maintains finished HTML and initial island markup. This is a corpus-bounded migration, not a general Docusaurus replacement.

Scenario definitions and cohort boundaries
  • Warm full: complete upstream yarn build; Nift force recomputation of conversion, bundles, projections and composition.
  • Fresh application state: generated application caches/output cleared; dependencies retained. Nift maintained OG source assets remain. This is not machine-cold.
  • Unchanged: complete normal production command with unchanged maintained inputs.

Upstream warm-full and unchanged use the same command, in separate chronological cohorts. Their differing medians reflect observed cohort variation, not different build algorithms. Docusaurus development server/HMR is not measured.

Event 004 / ownership

Fresh state exposes asset ownership.

OG cache / explicit maintenance

258.8s median upstream OG render duration

Clearing upstream application state also clears the OG cache. Its plugin regenerates the cards. Both Nift projects maintain the 792 unique accepted cards as static assets: normal publication copies them, and intentional metadata/title changes use an explicit selective refresh workflow.

Nift did not generate 792 cards in 26 seconds. The fresh-state result includes an intentional change in asset ownership.

Upstream also reclones the public cookbook during every prebuild. Authored Nift keeps a pinned maintained local snapshot; updating it is explicit maintenance. Upstream network acquisition remains visible in its complete command.

Publication versus maintenance-inclusive operations

Metadata publication excludes explicit OG refresh: whole operations were 4.936s authored and 2.144s rendered. Rendered island-source work includes explicit initial-markup maintenance; whole operation 12.229s versus 10.956s publication. Authored island-source 17.215s already includes its derived work.

Route-add OG setup occurred outside publication timing; no whole-operation duration is claimed. Rendered fixtures coordinate HTML, downloads and LLM views rather than deriving those views automatically. Explicit maintenance memory is outside publication RSS.

Shared layout and navigation still fan out. Rendered source is not uniformly faster: shared layout costs 9.941s versus authored 8.877s. Route lifecycle work remains substantial, and these are future profiling targets.

T8 fixed a real stale transitive imported-MDX TOC case affecting two pages. Eleven corruption-repair cases tested retained caches and products. Initial and rejected evidence remain available: optimization only counts after replaying the correctness gates.

Shared shell work, route/catalog invalidation, projection generation and component bundling remain costs. Some final rendered shared-change observations are slower than their initial probes; the result is evidence for future tooling work, not a promise that every row improves.

Event 009 / maintenance

Three codebases, three ownership tradeoffs.

Upstream Temporal Docusaurus

Established ecosystem, conventional Docusaurus/React tools, native component workflow and familiar contributor model.

Higher measured publication time and memory, expensive fresh-state work and broader production rebuilds.

Nift temporal (authored-source)

Markdown/MDX/frontmatter and structured references stay authoritative. Companion products derive automatically; explicit dependencies and retained React islands support faster production iteration.

Owns a bounded project compiler/cache/island adapter layer. Shared runtime and navigation changes still fan out.

Nift temporal-agent (rendered-source)

Fastest publication and very cheap body iteration; fewer routine transformations.

Maintainers coordinate HTML, initial island markup, downloads, LLM projections, metadata and navigation. Those representations can drift without explicit validation.

Event 010 / opinion

Prefer authoritative source for maintenance.

Agents implement, humans direct

Preferred: Nift temporal (authored-source)

One authoritative Markdown/MDX/frontmatter source derives companion products. Rendered-source speed does not outweigh the coordination burden. Publication time and measured memory improve over upstream, while retained React islands preserve practical interaction.

Humans and agents both edit

Preferred: Nift temporal (authored-source)

Human-readable source, reviewable diffs and familiar content organization. The iteration loop is fast enough, and fewer synchronized representations make maintenance easier.

Even if migration effort and incumbency were removed, Codex still prefers Nift temporal (authored-source) for both scenarios. This is an engineering judgement among all three implementations, not a benchmark-derived universal rule.

Event 011 / evaluation

A serious evaluation from Docusaurus to Nift.

The evidence supports Temporal seriously evaluating a migration from Docusaurus to Nift with retained React islands.

It does not establish an unconditional migration recommendation. Live search/backend/deployment integration, editor and component workflows, adapter/library upgrades and long-term compatibility ownership need evaluation. Docusaurus ecosystem benefits remain real.

Event 012 / guidance

Dogfood the migration guidance.

nift init --migration was used as intended; an older manual playbook did not replace it. No Nift core or migration-template changes were made.

Future guidance candidates: explicit transitive dependency inventories, route/catalog invalidation, shared-shell fan-out, projection ownership, island/OG maintenance and adapter review. Keep those proposals separate from this accepted migration.

Event 013 / methodology

Keep the measurement boundaries visible.

  • Five serialized samples for full/fresh/unchanged scenarios, rotating implementations on an active shared host. OS caches uncontrolled; fresh application state is not machine-cold.
  • Pinned sources, installed dependencies outside timing. Upstream cookbook network fetch remains inside its prebuild. Nift uses maintained OG assets and a pinned cookbook snapshot.
  • Changed-input cases are single observations, validated against independently forced output. Production publication is separate from unmeasured development/HMR.
  • Search UI parity uses fixtures; no live Algolia crawl/upload/backend claim. Deployment services were not benchmarked.
  • One upstream attempt returned success after a public GitHub HTTP/2 fetch failure produced an offline cookbook placeholder. Its wrong-corpus result was rejected; the unchanged exact command succeeded on retry without source changes. Raw log retained.
  • Complete Nift pipelines include project-side compilation, retained React, projections and publication. RSS scopes and excluded maintenance costs stay separate.
