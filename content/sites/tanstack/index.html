Finding 01

01

boundary

Move the boundary. Keep the product.

The target was the full public application, not a static imitation of its docs. Request-specific sessions, Router/Query behavior, real charts, search, chat/API boundaries and generated products remained part of the contract.

Nift tanstackAuthored-source / faithful

Maintained Markdown, frontmatter and structured references derive document AST, raw/download views and metadata. Nift composes prepared inputs; Start renders the public application.

Nift tanstack-agentRendered-source / agent-primary

Maintained TanStack document AST envelopes with explicit original/download projections. This is a hybrid runtime-consumed representation, not whole maintained HTML. More restructuring freedom did not relax parity.

React, Router, Query, Table and AI remain product dependencies where used. Start also supplies server functions, serialization and hydration. Vite is build tooling, not a required runtime library. Redact aliases, Tailwind, Content Collections, Sentry runtime and Cloudflare bindings remain explicit integration responsibilities.

03

parity

The migration failure was architectural.

Preserving behavior worked. Finding a worthwhile new ownership boundary did not.

7,527document contracts / 25 roots
333browser states / no page errors
24,224files / normal–forced byte equality

The Rsbuild candidate reproduced with independently installed frozen runtime dependencies and a separately locked adapter toolchain. All 244 maintained static assets match byte-for-byte. Required type, lint, unit, chat and desktop suites pass, with one existing desktop skip.

Real local Worker proofs preserve API boundaries, generated output, byte-identical request-time OG PNGs, fresh sessions, Markdown negotiation, mobile navigation, search navigation and the catalog renderer. No handler was replaced with a static success stub.

Browser semantics and interaction checks are not universal pixel identity. API/service proofs use controlled fixtures and unauthenticated boundaries; private live authenticated integrations are not certified. Hosted Algolia remains; there is no omitted local search-index build.

Vite's approximately 4.4 GiB process peak occurs around server emission. V8 live heap was much smaller at the sampled RSS peak, and heap caps did not materially remove that RSS peak. This does not establish a native allocator cause; overlapping diagnostic heap trials are not accepted timing comparisons. Rsbuild's own Node compiler becomes dominant around SSR completion.

This does not show that Nift itself has the same build cost or memory profile as TanStack Start. It shows that the migration retained too much of the existing runtime/build architecture for Nift to meaningfully change the dominant cost.

Nift composition is a nested component, not an additional cost to sum on top of content publication. Median components need not sum to a median total. These are complete orchestrated pipelines, not native @markup performance.

08

rejected splits

The deeper branches ended at real contracts.

×

C1 / branch terminated

A live backend cannot unfreeze a static shell.

Original backend forwarding worked and its request seed rotated. The Nift-published whole page retained the old seed. Required partner/session behavior therefore failed. Static output alone was not a faithful substitute.

×

C2 / branch terminated

Server-visible HTML was not the maintained authority.

Three real pages covered ordinary content, a table and tabs/code. Twelve scoped browser states initially matched. An HTML-only edit published normally and appeared in SSR, then vanished after the original interactive components mounted from their unchanged AST. A shadow AST would require coordinated maintenance; a clean HTML authority needs a different component/island boundary.

We stopped rather than weaken parity, fake dynamic functionality or reimplement substantial parts of Start. These bounded failures do not prove that every possible service/island design is impossible.

09

what worked

Useful work. An unconvincing migration.

  • Verified bundle reuseUnchanged publication avoids redundant application compilation.
  • Docs stay outside the heavy buildNormal document edits reuse the unchanged browser/backend bundles.
  • Correct publication and retirementCustom publisher, explicit dependencies, rename/delete handling and cache repair preserve outputs.
  • Independent recomputationNormal and forced output equality survives a fresh dependency install.

Those gains matter, but they do not make the entire application migration worthwhile. Full/fresh build cost, retained peak memory and compiler integration complexity remain. The source cache improvements do not transfer request-time HTML ownership.

Why publish a negative result?

Labs records what actually happens, including targets where migration is not compelling. Publishing the failed boundary makes the successful experiments more credible and keeps architecture fit separate from benchmark cherry-picking.

A new question. Not a promised rescue.

Next / plannednift init --rewrite

If TanStack.com were designed around Nift from the start, could it retain its public design and useful TanStack functionality with a better build and maintenance model?

The next phase, when resources allow, is a clean rewrite. Nift could own publication and composition; React and TanStack Router/Query/Table/AI could remain where useful; API, auth, chat and database work could have explicit service boundaries. Start would stay only if it earns its role. Lighter bundling and simpler source/projection ownership would be design choices, not assumptions.

What would count as a compelling rewrite?

  • Same or very close public design and UX
  • Preserved important interactive behavior and useful TanStack libraries
  • Substantially lower full-build peak memory
  • Materially faster fresh/full publication, cheap unchanged and incremental work
  • A simpler maintenance model
  • Agent preference for the rewrite in at least one maintenance scenario

The migration already dogfooded nift init --migration. The rewrite will test whether nift init --rewrite helps agents make larger architectural decisions instead of inheriting incumbent constraints. No rewrite has started and no success is guaranteed. Its services, complete costs and remaining weaknesses will need their own evidence.

12

conclusion

Do not migrate using this architecture.

We would not recommend migrating TanStack.com to Nift using the architecture tested here.

The retained runtime/backend build dominates, and the migration does not produce enough performance or memory benefit to justify the complexity. For both agent-led maintenance and mixed human/agent editing, the current assessment favors the original application architecture; among the two Nift migrations, the authored source has the stronger source-of-truth model.

A rewrite remains worth testing because it removes the inherited architectural constraint and asks a different question. If the benefits do not appear, that result belongs here too.
